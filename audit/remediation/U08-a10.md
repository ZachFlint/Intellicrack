### How the rewrite makes each covered behaviour a real gate

- **SectionInfo permission decoding** - oracle is the PE/COFF `IMAGE_SCN_*`
  bit specification (winnt.h constants), not the implementation. Drives `.text`
  (r-x), `.data` (rw-), `.rdata` (r--), zero (no perms), and full rwx
  characteristic words and asserts the exact decoded `is_executable` /
  `is_readable` / `is_writable` triples. Corrupting the bit masks in
  `SectionInfo` flips an assertion.
- **DataTypeInfo.display_type / FunctionInfo.summary+has_code /
  ToolFunction.signature / CrossReference+BreakpointInfo+ThreadInfo `__str__`**
  - each asserts an exact hand-derived formatted string (e.g.
  `"CheckLicense@0x401000 (fastcall, 1 vars)"`,
  `"BP#2 @ 0x401000 (hardware): disabled, hit 5 times"`). The expected string
  is computed by hand, never copied from output.
- **RegisterState** - asserts `__getitem__` resolves named registers, the
  `KeyError` error path for an unknown register name, and that `get_gpr_dict` /
  `get_segment_registers` partition registers into the exact expected key sets.
- **Exception hierarchy** - real `raise`/`pytest.raises` flows assert that
  `ProviderError` / `RateLimitError` / `AuthenticationError` / `AttachError` /
  `SandboxError` propagate full structured context (provider_name, status_code,
  response_body, retry_after, pid, vm_state, details) and are catchable at the
  correct base type.
- **Real SQLite round-trips through `SessionStore`** - `PatchInfo` (hex byte
  encoding), `Message`+`ToolCall`+`ToolResult`, `ToolState` (enum keys),
  `BridgeAnalysisSummary` (nested records), and a `BinaryInfo` built from a
  **real Windows PE** are persisted to a real on-disk SQLite DB via `save()` and
  reconstructed via `load()`, then asserted field-by-field against the
  originals. The oracle is the original object; the path under test is the real
  serialise/deserialise + DB layer.
- **Real PE -> core types integration** - `HexEditorBridge` parses
  `kernel32.dll` into section/import/export records that are assembled into
  core types; the `.text` section's decoded executable flag is checked, the
  SHA-256 is computed independently with `hashlib`, and the whole `BinaryInfo`
  survives a real DB round-trip. These tests run (not skipped) on this Windows
  host.
