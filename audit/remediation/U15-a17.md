# U15-a17 Remediation - tests/test_hexcore_e2e/test_binary_diff.py

## Context

The audited tests target the native `intellicrack_hexcore.diff_bytes` /
`diff_files` functions. The result dict returned by the real engine has
**exactly three keys**: `files_identical` (bool), `total_differences` (int) and
`regions` (list of `{offset_a, offset_b, length, diff_type}` dicts, where
`diff_type` is one of `match`, `modified`, `inserted_a`, `inserted_b`). Verified
directly against the installed module and the Rust source
(`src/intellicrack-hexcore/src/lib.rs` `diff_result_to_py`,
`src/intellicrack-hexcore/src/diff.rs`).

A prior remediation pass had introduced a `similarity` key into every assertion;
that key does not exist in the production result dict, so those assertions could
not have passed against the real module. This pass removes the invented field
and replaces every weak/OR/tautological assertion with exact region-list and
scalar equality backed by an independent `difflib.SequenceMatcher` Myers oracle
(used where the two Myers implementations provably agree) or by the byte content
itself. `total_differences` is independently re-derived from the region list in
`_assert_total_differences_consistent`.

## Falsifiability

Each test asserts exact region lists / scalars, so corrupting the engine
(wrong `diff_type`, wrong offset/length, wrong `total_differences`, a missing
schema key, or swallowing the read error) turns the corresponding test RED.
