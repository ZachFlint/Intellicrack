## Supporting production fixes (genuinely missing functionality)

The Rust-transform tests were order-dependent: `intellicrack_hexcore` installs
its compiled extension as a submodule of a namespace package, so
`import intellicrack_hexcore; mod.HexDocument` only resolved when some other
import had already loaded the inner extension. Run in isolation, the Rust
transform tests raised `AttributeError: module 'intellicrack_hexcore' has no
attribute 'HexDocument'`. Made resolution deterministic in both consumers by
also importing the inner extension and selecting whichever module exposes
`HexDocument`:

- src/intellicrack/core/transform_pipeline.py
- src/intellicrack/bridges/hex_editor.py

A test-fixture defect was also fixed: the toolbar window restored tab layout
from the global `QSettings("Intellicrack", "MainWindow")` store, which on a
developer machine contains a real persisted hex-editor tab whose restoration
needs a bridge the test orchestrator does not register (setup error
`ToolError: bridge not available`). The `narrow_window` fixture now redirects
QSettings to a temporary INI store and clears it, so the window starts from a
clean, reproducible state without mutating the user's real settings.
