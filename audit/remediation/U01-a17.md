# Remediation U01 - agent-17.md - tests/test_providers/test_e2e_chat.py

All 48 findings remediated by rewriting the live end-to-end provider chat suite
into real gates. The implementation-independent oracles introduced are:

- the known-correct answer to `2 + 2` (`4` / `four`) for the cross-provider math
  check;
- the exact Windows target path `C:\Windows\notepad.exe` that a tool call must
  echo back through the bridge's argument parser (verified live: Grok returns
  `arguments["path"] == "C:\\Windows\\notepad.exe"` and `tool_name == "binary"`);
- per-vendor documented model-identifier conventions confirmed against live
  listings (`claude`, `gemini`, `grok`, `/` for org-scoped HF/OpenRouter ids) and
  realistic context-window floors (Anthropic 200000, OpenAI min 8192, Google min
  8192, OpenRouter min 4095, Grok 131072, HF 4096);
- the configured chat-model constant that must appear in the listing where the
  live API actually returns it (`gpt-4o-mini` in the OpenAI listing,
  `openai/gpt-4o-mini` in the OpenRouter listing, the active Ollama model in the
  Ollama listing); Grok and HF list models that do not include the small chat
  model used for chat, so those listing gates assert vendor id convention +
  capability fields instead;
- greeting tokens and a readable-character ratio for chat/stream relevance;
- a tight `max_tokens=32` -> `<= 45` word cap (live runs produced 27-30 words);
- a both-facts-recalled (`archimedes` AND binary/analysis) multi-turn assertion;
- HTTP 4xx client-rejection status pulled from the exception chain for invalid
  model errors, plus an OpenAI-specific "model ... does not exist" message check;
- a deterministic transport-timeout gate against a non-routable endpoint, which
  does not depend on live-account billing state.

No mocks, patches, or synthetic responses were introduced; every gate drives the
real provider bridge end to end. The HuggingFace tool-calling `xfail` was removed
and replaced by a faithful schema round-trip plus a typed-error-translation gate.
