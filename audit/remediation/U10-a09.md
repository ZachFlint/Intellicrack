## Approach

Every flagged test was rewritten into a real falsifiable gate. The suite now
drives the real `SandboxBridge` through a **real** `SandboxManager` populated
with **real** sandbox objects registered via the production
`register_existing_sandbox`. Nothing the test claims to verify is mocked:

- **QMP / cont()** — a real in-process `asyncio` QMP server on loopback feeds a
  **real `QMPClient`**, which negotiates capabilities and exchanges real
  `{"execute":"cont"}` frames. Server modes drive the real success path, a real
  QMP error frame, and an abrupt disconnect that makes the real client raise.
- **Analysis methods** — the **real `intellicrack.sandbox.analysis`** functions
  run. Failures are induced with genuinely malformed real report data (a
  `NetworkActivity` record missing `remote_port`) that makes the real code raise
  a real `KeyError`. Success paths are checked against the analysis functions
  used as independent oracles.
- **Guest agent** — a real `GuestAgentClient` queue holds real
  `GuestAgentMessage` dataclasses (and a deliberately malformed `object()`),
  drained by the real `get_pending_messages`.
- **YARA / snapshot / gating** — real `SandboxBase` subclasses implement the
  operation under test; the bridge's faithful argument pass-through and result
  forwarding are asserted exactly.

No private members are accessed: QMP/agent/VNC injection uses real
`QEMUSandbox`/`GuestAgentClient` subclasses that expose the objects through the
public property surface; the availability cache is seeded through the public
`availability_cache` property.
