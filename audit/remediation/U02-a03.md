# Remediation U02-a03

File owned: `tests/test_audit7/sandbox_qemu/test_anti_evasion_identity.py`
Source report: `audit/agent-03.md` (findings F-0022 / F-0029 regression suite).

## Root-cause theme

Every flagged test was tautological or vacuous: it compared the production
`_anti_evasion_identity()` helper against itself (via `_anti_evasion_smbios_entries()`,
also derived from the same helper) or against hard-coded parametrize values that
mirrored the implementation, and the running-sandbox path used a `MagicMock()` QMP
client.

The rewrite introduces an **independent oracle** `_EXPECTED_IDENTITY` (a hand-maintained
F-0029 spec dict, deliberately separate from the production mapping) and threads each
profile through the **real production consumers**:

* the actual `-smbios` launch-arg string built by the real `_build_qemu_command()`
  (decoded by an independent parser, not by calling the helper), and
* the actual `reg.exe /d` value dispatched by the real `apply_anti_evasion()` through a
  recording guest-agent transport.

The `MagicMock()` QMP was replaced with a real, unconnected `QMPClient` (a genuine
production object that opens no socket). The `_RecordingAgent` remains as a faithful
emulation of the in-guest `Test-AllowedCommand` allowlist transport boundary, not of the
operation under test.
