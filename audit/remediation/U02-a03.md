## Summary

All eight audit findings on this file were anti-patterns (vacuous/tautological
assertions, can-fail-only-on-trivia, method-to-method comparisons within the
same class). The current file is a full rewrite into real falsifiable gates that
drive the real production code (`QEMUSandbox.apply_anti_evasion` and
`QEMUSandbox._build_qemu_command`) through:

* a **non-mock** `_RecordingAgent` (a real `GuestAgentClient` subclass that
  records dispatches and replays the in-guest `Test-AllowedCommand` allowlist),
  and
* an **independent oracle** `_EXPECTED_IDENTITY` -- a hand-maintained
  module-level constant of the required `(manufacturer, product)` per profile,
  kept separate from the production `_anti_evasion_identity` mapping so a
  production regression cannot regress the expected value in lockstep.

Production source was **not** modified (pytest runs against the installed main
`src`). Falsifiability was verified in-process by overriding the identity helper
to inject a corrupted product string and observing it propagate into the
dispatched `reg.exe /d` value (which the exact-value assertions against
`_EXPECTED_IDENTITY` would reject), and by confirming bare `reg.exe` is rejected
by `is_windows_allowlisted` and differs from `WINDOWS_REG_EXE_PATH`.
