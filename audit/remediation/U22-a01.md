# U22-a01 Remediation (Salvage Attempt 2)

## Summary

The prior run left a **flaky** gate for finding 1: it captured the oracle via
`get_memory_map(resolve_names=True)` and then drove `_refresh_regions`, which
performs a *second, independent* live enumeration of the same address space.
Because the multithreaded test process mutates its own memory map between the
two snapshots, the region count (and individual region sizes) disagreed
intermittently (`FAIL, PASS, PASS`).

The fix replaces the two-enumeration design with a **single captured snapshot**.
One real, unmodified `ProcessBridge.get_memory_map(resolve_names=True)`
enumeration is taken once and replayed through a `_FrozenMemoryMapBridge` so the
oracle and the production rendering path (`MemoryTab._refresh_regions` ->
`_on_success`) consume the **identical** real capture. The rendering closure
under test is never mocked; only the source enumeration is pinned to one read.
Comparison is indexed by base address (the table self-sorts), with row count and
every cell (size, protection, state, type, module) asserted exactly. Confirmed
deterministic across repeated isolated runs and confirmed RED when the
production size formatter is corrupted (`size // 2`).

Findings 2 and 3 were already sound real gates and were left in place.

### Notes on the 3 skips

The 3 skipped tests in `test_realcov_12a_manager_real.py` are marked
`@pytest.mark.spawns_process`; the conftest hook refuses to spawn external
processes on the bare host. They are genuine environment-capability skips, not
masked breakage: running with `INTELLICRACK_ALLOW_HOST_PROCESS_TESTS=1` executes
all 10 sandbox tests and they pass (`10 passed`). Finding 3's gate
(`test_absent_/test_present_real_qemu_binary_*`) does not spawn a process and
runs unconditionally as part of the 11 passing tests.

### Determinism verification (finding 1)

`test_region_map_rows_round_trip_real_memory_regions` was run 3x in isolation
(`-p no:randomly`): `1 passed` each time. Falsifiability: corrupting the
production size formatter to `f"0x{size_val // 2:X}"` made the test fail with
`AssertionError: size mismatch at base 0x7FFE0000`; the original code restored.
