## Falsifiability checks performed

- Branch oracle is red-on-corruption: feeding a wrong computed value selects the `else`/`bug` branch (verified: `v=999` against `if (v==7)` yields the `wrong` field, not `correct`). A broken arithmetic/bitwise operator therefore drives `_names(results)` to a different list and the test fails.
- Read-back oracle is red-on-corruption: `byte@70 == [70]` differs from `byte@71 == [71]` in `bytes(range(256))`, so a mis-computed placement offset reads a distinguishable byte and fails the `raw_bytes` assertion.

## Changes

The file at HEAD already implemented the value-oracle and offset-plus-byte oracle strategies the fix recommendation requested. The pre-existing comparison/logical branch-name oracles already encode the boolean outcome in the selected field name and were left as-is (the name selection is itself the falsifiable witness).
