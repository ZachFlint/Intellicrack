## Additional defects fixed this attempt (the rejection reasons)

1. **PATH clobbering regression (defects 1-4).** `window_with_hxd_available` set
   `PATH=str(install_dir)` and `window_without_hxd` /
   `test_main_window_constructs_without_exception` / `test_registration_flips_with_path_state`
   set `PATH=""`. Emptying/replacing the whole PATH broke `MainWindow.__init__` ->
   `_restore_window_state` -> `add_hex_editor_tab` -> `get_hex_editor_bridge`
   (`ToolError: bridge not available`) and `_refresh_system_status`
   (`RuntimeError: no running event loop`). Fixed by **prepending** for the available case
   (`install_dir + os.pathsep + original PATH`) and **leaving PATH intact** for the
   unavailable case (the host has no HxD anywhere, asserted by the new `_host_has_any_hxd()`
   precondition). The unit-level `TestFindHxDExecutableRealDetection` tests were left as-is
   since they never construct `MainWindow`.
2. **Leaked global QSettings state (order-dependence, the 8 fixture ERRORs).**
   `MainWindow.closeEvent` -> `_save_window_state` persists its default "Hex Editor" tab to the
   global `("Intellicrack","MainWindow")` QSettings; the next `MainWindow` restored those tab
   names and tried to recreate the hex-editor tab via `add_hex_editor_tab`, raising
   `ToolError` in these lightweight test windows. Added an autouse `isolated_window_settings`
   fixture that redirects QSettings to a per-test INI under `tmp_path` (IniFormat default +
   User/System scope paths) and clears it, so every construction starts from a clean,
   deterministic persisted state and the suite never mutates the real user's settings.

   Stability verified across 5 random seeds (1, 42, 2193208088, 7, 99999) and in
   `-p no:randomly` deterministic order: 17 passed each run, ~10s (matching the pre-rewrite
   baseline runtime, not the prior ~118s failing run).
