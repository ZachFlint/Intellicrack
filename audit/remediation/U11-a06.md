suite patched `run_bridge_coroutine_async` with a fake runner that invoked
`on_success`/`on_error` synchronously, bypassing the real async dispatch). The
prior run replaced that pattern with a real gate: every `SystemTab` slot now

thread via real queued signals. The only double is the awaitable bridge method
itself (`_RecordingAsyncMethod` = the external tool the bridge wraps), which
returns a genuine coroutine the real worker awaits. Synchronisation is explicit
via `_pump_until`, which spins the real Qt event loop until the production
callback mutates observable state or a bounded deadline fails the test.

This salvage run verified each finding is a real gate and fixed the two
remaining `pydoclint` DOC301 violations (merged `__init__` docstrings into the
class docstrings for `_RecordingAsyncMethod` and `_StubBridge`) so all six
