## Re-fix focus (test-reviewer rejection, attempt 2)

The prior attempt removed the `QMessageBox`/`QFileDialog` monkeypatch mocks but
replaced them with tests that drove the **real modal dialogs**, which block
forever under the real `qapp`/`QApplication`. Two tests hung indefinitely and
the file-level `pytest` run could never report green:

- `test_import_of_malformed_json_does_not_register_or_notify` -- the malformed
  JSON drives the real except-branch in `templates.py` `_import_template_from_path`,
  which called `QMessageBox.warning(...)` (modal, never returns).
- `test_unsupported_format_creates_no_bookmarks_and_no_events` -- the non-PE/ELF
  buffer drives the else-branch in `_on_auto_bookmark_structure`, which called
  `QMessageBox.information(...)` (modal, never returns).

### Fix (production decoupling + non-modal injectable reporter)

`src/intellicrack/ui/panels/hex_editor/templates.py` was changed to separate the
registry / bookmark mutation logic from the user-notification side-effect. A new
`TemplatesMixin._notify_user(title, message, level)` helper routes notifications
through an injectable `_user_notifier` reporter when one is attached (headless
orchestration / bridge / tests), and otherwise falls back to the modal
`QMessageBox.warning` / `QMessageBox.information`. The two call sites now call
`_notify_user(...)` instead of constructing modal dialogs directly. No behaviour
changes for the real GUI (the `QMessageBox` fallback is unchanged when no reporter
is set).

The test harness supplies a real `UserNotificationRecorder` (a plain callable that
records `(title, message, level)`), so the negative-path assertions run to
completion with **no `QMessageBox` monkeypatching and no blocking dialog**. The
recorder also lets each test assert the *exact* notification the production
except / else branch would surface, proving the branch executed rather than
silently no-opping.
