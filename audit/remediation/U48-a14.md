# U48-a14 Remediation - tests/test_core/test_logging.py

Source audit: agent-14.md. Unit owns `tests/test_core/test_logging.py` (8 findings).

All eight findings flagged the `ColoredConsoleRenderer` tests for weak,
substring-presence-only assertions on the rich rendered log line (only checking
that `"INFO"` / a color code / `"extra_key="` appeared *somewhere*). Each was
rewritten to assert the **complete rendered line** against a fully literal,
hand-written expected constant. The literal is an independent oracle: it
encodes the universally-standard ANSI SGR color codes (green=32, cyan=36,
yellow=33, red=31, magenta=35), the eight-column-padded level label, the
ESC[0m reset, the `module:func:line` location and the event - with no production
format logic re-derived inside the test. Driving a real
`ColoredConsoleRenderer.__call__` over a realistic structlog event dict to a
verified literal string makes every structural regression (wrong color, wrong
padding, missing reset, reordered fields, stray/missing bracket) fail.

Falsifiability confirmed: swapping the production `info` color from green to red
makes the literal-constant assertion go red.
