## Root-cause fix for the prior rejection (notes 1-4)

All 9 prior pytest failures were a stale-build-vs-source mismatch, not a test-logic
defect. The installed native module
`D:\Intellicrack\.pixi\envs\default\Lib\site-packages\intellicrack_hexcore\intellicrack_hexcore.cp313-win_amd64.pyd`
(dated 5/1) predated the current `src/intellicrack-hexcore` source and exposed a
5-arg CRC signature and a 512-bit blake2b. The previous attempt rebuilt the wheel but
could not install it (file lock) and only shadowed it via `PYTHONPATH`, so the
reviewer's plain `pixi run pytest` still loaded the stale `.pyd`.

This attempt actually replaces the importable module:

1. Rebuilt from current source: `pixi run maturin develop --release` (wheel built
   cleanly to `src/intellicrack-hexcore/target/wheels/intellicrack_hexcore-0.1.0-cp313-cp313-win_amd64.whl`).
2. The in-place install was blocked only because the old `.pyd` was memory-mapped by
   unrelated concurrent Python processes. On Windows an in-use DLL can be renamed but
   not overwritten, so the stale `.pyd` was renamed aside to `*.old_*` (a name Python
   never imports) and the freshly built `.pyd` from the wheel was copied into the
   canonical filename.
3. Verified in a fresh interpreter against the now-importable module:
   - `compute_hash("blake2b")` -> 64 hex chars and `== hashlib.blake2b(data, digest_size=32).hexdigest()` (256-bit, matches `Blake2b<U32>` in `src/hash.rs`).
   - `compute_hash_custom_crc((0,256), 0x04C11DB7, 0xFFFFFFFF, 32, (True,True), 0xFFFFFFFF)` accepted (6-arg signature, matches `src/lib.rs:688`) and `== binascii.crc32` reference.

No production source and no test logic was altered to force green; the delivered test
expectations already matched current source. Only the built artifact was brought back
in sync.
