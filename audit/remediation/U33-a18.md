# Remediation U33-a18

Unit: `tests/test_audit7/sandbox_qemu/test_start_calls_agent_connect.py`
Source report: `audit/agent-18.md` (audit7 F-0002)

## Root cause of the findings

All three flagged tests patched the production `GuestAgentClient` constructor
itself with a mock factory returning a `_RecordingAgent` stub, so the real
`GuestAgentClient.connect` (real `asyncio.open_connection` socket loop, real
retry handling, real reader task) was never exercised. The tests only proved
that a canned stub's `connect_calls` list got an entry or that a canned return
value/exception produced a `SandboxError`. If the real client's connection
logic broke, the tests would stay green.

## Fix approach

The rewrite drives the **real, unmocked** `GuestAgentClient.connect` and the
**real** production `QEMUSandbox._ensure_agent_connected` wrapper end to end
against real loopback TCP endpoints. Only the helpers that genuinely require an
installed QEMU binary / QMP monitor / in-guest agent are neutralised, via
real (non-mock) subclass overrides that perform no I/O (`_spawn_qemu_process`,
`_connect_and_verify_qmp`, `_bootstrap_guest_agent`, `_resolve_qemu_pid`,
`_register_qemu_pid`, `_prepare_qemu_shared_folders`, `_create_guest_agent_script`,
`_cleanup`, `is_available`). The agent-connect step is left fully real:
`_attach_qemu_agents` constructs an `_ArgCapturingAgent` (a real subclass that
records the `time_limit` argument and then calls `super().connect`, i.e. the
production socket loop) and invokes the unmodified production
`_ensure_agent_connected`. No `unittest.mock` / `MagicMock` / `patch` is used
anywhere in the file.

Success path stands up a real `asyncio.start_server` on the configured agent
port; failure paths point the real client at a genuinely closed (reserved then
released) loopback port so the connection is really refused.

## Falsifiability check (empirical)

Mutating production `_ensure_agent_connected` to `connected = True` (skipping
the real `await agent.connect(...)`) turned exactly the three connect tests RED
(`3 failed, 3 passed`); reverting restored `6 passed`. The remaining green
tests (config defaults, timeout-budget) correctly do not depend on that line.
Production source was reverted and shows no diff.
