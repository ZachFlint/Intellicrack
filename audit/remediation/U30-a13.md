# Remediation U30 (agent-13.md)

Unit: tests/test_audit4/a1_sandbox_manager_caching/test_availability_caching.py

## Root cause of all three findings

Every flagged test replaced the operation under test (`SandboxManager._probe_type`)
with a `unittest.mock` fake (`patch.object` / `AsyncMock`). The caching contract
was asserted against a fake counter or a fake `True`, so the real OS-level probe
path (`where WindowsSandboxClient.exe` + CIM `Win32_OptionalFeature` query for the
Windows sandbox; `qemu-system-x86_64` discovery for QEMU) was never exercised. The
file also imported `unittest.mock`, violating the no-mocks rule.

## Fix approach (applies to the whole file)

- Removed all `unittest.mock` usage from the file.
- Introduced `_RecordingManager(SandboxManager)` whose `_probe_type` calls
  `super()._probe_type(...)` — the **real production probe runs end to end** for
  every call; the subclass only appends the type to `probe_calls` so the test can
  count how many times the caching layer reached the live probe. No fake result
  is ever substituted.
- Added `_oracle_availability()`: an **independent oracle** that constructs fresh,
  real `WindowsSandbox` / `QEMUSandbox` instances and queries their real
  `is_available()` directly (no manager, no cache). Expected availability is taken
  from this oracle, never frozen from the manager's own output.

## Additional hardening (same file, beyond the three findings)

To eliminate every remaining mock of the operation under test, the failure-TTL and
invalidation tests were also migrated to `_RecordingManager`: they now count real
probe invocations and (where applicable) assert the re-probed/refreshed cache entry
equals the independent oracle and carries a fresh timestamp. Pure dataclass tests
(`AvailabilityCacheEntry.is_expired`) and direct-injection cache tests are unchanged
and assert exact boolean/structure values.
