## Oracle Justification

- **find_pattern offset**: `ctypes.addressof(buf)` is the independently known address of the allocated buffer; the bridge must find it exactly.
- **scan_memory matched_bytes**: `binascii.hexlify(marker).decode()` is a separate stdlib function that produces the reference hex encoding.
- **ntdll .text characteristics**: `pefile.PE('C:/Windows/System32/ntdll.dll')` reads the on-disk PE header to give the authoritative characteristics value (`0x60000020` = `IMAGE_SCN_MEM_EXECUTE | IMAGE_SCN_MEM_READ | IMAGE_SCN_CNT_CODE`); the bridge reads the in-memory image.
- **ntdll exports**: `NtCreateFile` at ordinal 297 and `RtlAllocateHeap` at ordinal 754 are stable Windows NT API ordinals, verified via pefile on this system (2516 exports, 0 duplicates).
