TASK: Design and build a complete, end-to-end Inno Setup installer for Intellicrack
(D:\Intellicrack) that installs the entire application on a clean Windows machine
with ZERO preinstalled prerequisites. The output is a single Setup.exe that yields
a fully working Intellicrack — GUI, all tool bridges, and the QEMU sandbox —
without the user installing Python, Java, Rust, any RE tool, or anything else.

This is a NEW TASK. Before writing any code, use AskUserQuestion to lock the
decision forks listed at the bottom. Then follow the mandatory verification pass.

- Build/dep config lives in pyproject.toml under [project] (dependencies,
  optional-dependencies: dev/test/docs/profile/ml) and [tool.pixi] (conda
  `dependencies` + `pypi-dependencies` + tasks). requirements.txt is autogenerated
  — never edit it. Platform is win-64 only, Python 3.13, channel conda-forge.
- Live env at .pixi\envs\default resolved ~454 packages; all core runtime + ML
  imports succeeded (cryptography, pyghidra, jpype, yara, PyQt6, pywebview,
  pefile, lief, capstone, keystone, frida, r2pipe, rzpipe, ghidra_bridge,
  anthropic, openai, google.genai, mcp, ollama, torch, transformers, etc.).
- Native components (already built on this machine; end users must NOT need
  compilers):
  - intellicrack_hexcore — Rust/PyO3, built via `just build-hexcore`
      (maturin develop --release). It installs into the env's site-packages; it
      is NOT a declared pixi package. Confirm how it lands and capture it in the
      staged runtime.
  - x64dbg plugin — C++ built via `just install-x64dbg-plugin`
      (cmake+ninja from pixi + system MSVC on the BUILD machine only). Prebuilt
      artifacts observed at tools\x64dbg\release\x64\plugins\intellicrack_bridge_x64.dp64
      and ...\x32\plugins\intellicrack_bridge_x32.dp32 — ship these prebuilt.
- External tools live under <project_root>\tools and the WHOLE tree is gitignored
  (~119 GB). Observed: ghidra\ (11.4.2), radare2\bin\radare2.exe (for r2pipe),
  cutter\rizin.exe (for rzpipe), cutter\cutter.exe, x64dbg\release\{x64,x32}\,
  qemu\ (qemu-system-x86_64.exe + qemu-img.exe + DLLs), NASM\nasm.exe, plus
  resource_hacker, pmd, google-java-format, AdobeInjector, IDMActivator,
  WindowsPatch. Inventory the REAL tree; confirm which are actually referenced by
  code vs incidental.
- Ghidra needs JDK 21 (tools\ghidra\Ghidra\application.properties:
  application.java.min=21). No JDK is bundled in tools\ghidra. The bridge's JVM
  resolver GhidraBridge._discover_jdk() (src\intellicrack\bridges\ghidra.py, ~line
  1760) prefers any existing JAVA_HOME UNCONDITIONALLY (only checks that a `bin`
  dir exists — NO version check), then falls back to tools\ghidra\jdk-*. On this
  host JAVA_HOME points at a JRE 8, which Ghidra rejects. THE INSTALLER STRATEGY
  DEPENDS ON bundling Temurin JDK 21 as tools\ghidra\jdk-21.x AND on fixing
  _discover_jdk to validate the major version so a stale system JAVA_HOME cannot
  shadow the bundled JDK. Treat that source fix as an in-scope prerequisite (with
  a falsifiable test), or explicitly justify an alternative (e.g. the launcher
  forcing JAVA_HOME to the bundled JDK).
- QEMU guest images (tools\qemu\images: 8.4 GB Win11 ISO + multi-GB qcow2s) are
  NOT shippable. The Debian guest (~800 MB) may be optionally downloaded on
  demand. Windows guests must be user-provided (licensing). Sandbox backends:
  QEMU (bundleable, self-contained), Docker (NOT bundleable; runtime-detected,
  daemon was down), Windows Sandbox (Windows optional feature).
- Tool paths resolve from get_project_root()\tools via src\intellicrack\core\
  config.py. Entry points: `intellicrack = intellicrack.main:main`,
  `python -m intellicrack`, GUI `python -m intellicrack.ui.app`; pixi tasks
  dev/gui. hexbench (src\hexbench) is a separate stdlib-only pywebview GUI —
  decide whether it's in scope.
